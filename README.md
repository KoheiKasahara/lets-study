# レッツスタディ（Let's Study）

子供向けの学習クイズアプリです。バックエンドなしの静的Webアプリ（React + TypeScript + Vite）です。

## コンセプト

- **いまの対象は保育園児**：文字は大きく、文章はひらがな中心です。
- **成長に合わせて少しずつ拡張**：対象年齢が上がったら、漢字の問題や計算・英語など、カテゴリや問題を足していける構造にしています。
- **興味ベースでクイズ化**：学校の勉強だけでなく、そのとき子供が興味を持っているもの（例：国旗、動物、乗り物…）をカテゴリとして追加できます。
- **基本の流れ**：カテゴリを選ぶ →（難易度を選ぶ）→ 10問ずつのセットで答える → セットごとに「つづける／もどる」を選ぶ。一度出た問題はそのセッションでは二度と出ません。
- **クイズの仕組みは共通基盤**：セッション管理・10問セット・重複なし・難易度（任意）の動きは「クイズ基盤」として切り出してあり、他のアプリでも同じ動きを再現できます。仕様は [docs/quiz-foundation.md](docs/quiz-foundation.md) を参照。

## モンスター育成

クイズに答えると経験値がたまって、ドット絵のモンスターを育てられます。

- **スターター**：ホームの「モンスターを そだてる」から、基本種族6種（ほのお・みず・はっぱ・でんき・いわ・ほし）から1匹を選んでもらいます。
- **経験値と進化**：正解で +10 XP、まちがえても頑張った分 +3 XP が、セット終了時に所持モンスター全員へ入ります。Lv5で第2段階、Lv10で第3段階へ進化し、見た目（ドット絵）と名前が変わります。結果画面に「○○ XP たまった！」と成長が表示されます。
- **たまご**：累計正解数が30問ごとに「たまご」が1つもらえ、タップで新しい種族が孵化します。たまごが無いときは、育成画面に「あと○問 せいかいすると たまごが もらえるよ」と進み具合が出ます。
- **配合（ごうたい）**：持っているモンスター2匹を選ぶと、新しいモンスターが1匹生まれます（親は残ります）。子は「親Aの形 × 親Bの色」で描かれ、名前は親2匹の名前の前半＋後半の合成名、ステータスは両親の平均＋世代ボーナスです。配合モンスター同士の再配合もできます。選ぶたびに「あと○ひき えらんでね」と案内が出て、「ごうたい！」ボタンは画面下のバーに貼り付くので、スクロールしなくても押せます。
- **パーティ**：育成画面でカードの ☆ を押すと、お気に入りの最大3匹でパーティが組めます（★で入り、もう一度押すと外れます）。並び順がそのまま闘技場で戦う順番になります。
- **闘技場**：ホームの「とうぎじょう」で戦います。パーティを組んでいるとチーム戦になり、パーティの並び順に出場して、ねむったら次のメンバーが自動で出てきます（CPUも3匹のチームです）。パーティが空のときは、モンスターを1匹選んで1対1で戦えます。ステータスは HP・こうげき・ぼうぎょ・すばやさの4種で、すばやさ順に攻撃します。バトルの速さは「ふつう／はやい」で切り替えられ、終わったら同じパーティ（モンスター）のまま、すぐにもう一度戦えます。勝つとトロフィーと経験値、負けても少しの経験値が、参加した全員に入ります。相手が倒れる表現は「つかれて ねむった」に統一しています。
- **ドット絵**：見た目はピクセルマップ（文字列配列＋パレット）で定義し、SVG の rect で描画します（`src/monsters/species.ts`、`src/components/PixelMonster.tsx`）。
- **保存**：所持モンスター・パーティ・累計正解数・たまご・トロフィーは localStorage（キー `lets-study:monsters:v1`）に保存されます。壊れたデータでも落ちないよう読み込み時に検証します（パーティ欄の無い旧セーブは空パーティとして読み込めます）。
- ロジック（経験値・進化・配合・ステータス・バトル・保存）は UI から分離した純粋関数として `src/monsters/` に置き、単体テスト付きです。

## 対応する画面

PC・スマホ縦・スマホ横のすべてで、横スクロールなしで遊べます。

- 文字サイズと余白は画面に合わせて伸び縮みします（`src/styles/tokens.css`）。
- 横長の画面（横向きスマホ・タブレット・PC）では、クイズは「左に問題、右に選択肢」の2カラムになります。
- 答え合わせの帯は、画面からはみ出すときは下端に貼り付くので、スクロールせずに次へ進めます。
- ノッチやホームバーのある端末でも、端が隠れないようにしています（safe-area 対応）。
- ホーム画面に追加すると、アプリのように全画面で開けます（`public/manifest.webmanifest`）。

## CI / デプロイ

- **CI**（`.github/workflows/ci.yml`）：pull request と main への push で、
  format チェック・lint・テスト・ビルド（型チェック込み）を自動実行します。
  結果は各実行の Step Summary にサマリ（成否とテスト件数）が表示されます。
  main への直接 push は禁止で、必ずブランチ → プルリクエスト経由にします（CI が合格しないとマージ不可）。
- **デプロイ**（`.github/workflows/deploy.yml`）：main への push（と手動実行）で GitHub Pages へ自動デプロイします。
  Pages 用ビルドでは Vite の base が `/lets-study/` になります（環境変数 `VITE_BASE` で切り替え、通常ビルドは `/`）。
  公開URLはデプロイ実行の Step Summary に表示されます。
  初回はワークフローが Pages を有効化します（`configure-pages` の enablement）。リポジトリ設定で Pages の公開元が「GitHub Actions」になっていれば追加の手作業は要りません。

## 開発手順

Node.js 22 以上を使います（`.nvmrc`）。

```bash
npm install          # 依存関係のインストール
npm run dev          # 開発サーバ起動
npm run check        # format・lint・型チェック・テスト・ビルドを一括実行（PR前に必ず）
npm run format       # Prettier で整形
npm run test:watch   # テストを監視モードで実行
npm run preview      # ビルド結果のプレビュー
```

## カテゴリの追加方法

クイズはデータ駆動の構造になっているので、**データを追加するだけ**でカテゴリを増やせます。画面やエンジンのコードを変える必要はありません。

1. `src/data/categories/` にファイルを作り、`CategoryQuiz` 型のデータを定義する
   - カテゴリ：`{ id, name, icon（絵文字）, color（カードの背景色）, description }`
   - 問題：`{ question, visual（絵文字・任意）, choices（必ず4つ）, answerIndex（0〜3）, explanation（任意）, id・tags・group（任意） }`
   - 難易度（任意）：`difficulties: [{ id, label, choiceCount（表示する選択肢数）, poolTag（プールを絞るタグ）, distractors（誤答の選び方） }]`。付けなければ難易度なしでそのまま動く
   - 型定義は `src/types.ts` を参照
2. `src/data/index.ts` の `allQuizzes` に追加する

手本は `src/data/categories/animals.ts`（ふつうのカテゴリ）と `flags.ts`（データから問題を生成する例）です。
追加したデータは `src/data/data.test.ts` の整合性テスト（問題数・選択肢数・正解インデックスの範囲）で自動チェックされます。
